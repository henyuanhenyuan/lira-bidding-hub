# 影刀 RPA 采集交付包

目标：让运营用影刀自己采集竞品数据，导出 CSV 后直接投递，全程无需写代码。

## 一、采集机要求

| 项 | 要求 | 原因 |
|---|---|---|
| 系统 | **Windows 10/11** | 影刀是 GUI 自动化，不能跑在 Linux 服务器 |
| 浏览器 | Chrome，保持淘宝登录态 | 影刀驱动真实浏览器 |
| 机器 | 8C/16G，常开不休眠 | 夜间运行 |
| 网络 | 稳定出口，不与其他代理共用 | IP 质量影响成功率 |
| 调度 | 避开整点（如 02:17 / 09:43） | 降低被识别概率 |
| 频率 | 每日 2–3 次，不要更高 | 高于此无业务价值 |

## 二、影刀流程设计

```
读取 targets.csv（target_id, url）
  → 循环打开每个链接
  → 等待页面稳定
  → 提取字段（标价 / 券 / 活动 / 标题 / 主图 / 库存）
  → 截图存证
  → 追加写入 snapshots.csv
  → 全部结束后 POST /v1/import/csv（失败则留文件，等收件箱轮询）
```

**关键原则**：

- **只采集原始观测**，不要自己算到手价——到手价由服务端统一计算，否则口径不可比。
- **抓不到就留空**，不要填 0。空 = 未知，0 = 免费，两者差别巨大。
- **单条失败不中断整批**，记录错误码继续下一条。

## 三、字段契约

见 `snapshots.example.csv`，列定义：

| 列 | 必填 | 说明 |
|---|---|---|
| `target_id` | 是 | 与 `targets.csv` 一致的稳定 ID |
| `ts` | 是 | ISO 8601，带时区，如 `2026-10-24T02:17:00+08:00` |
| `collector` | 否 | 采集源标识，默认 `yd-v1`；变更会触发换源抑制 |
| `source_tier` | 否 | 0 官方 / 1 三方 / 2 授权 / 3 公开页面 / 4 人工 |
| `list_price` | 是 | 页面标价，**不要填到手价** |
| `coupons` | 否 | JSON 数组，如 `[{"kind":"shop","threshold":299,"discount":30}]` |
| `promotions` | 否 | JSON 数组，如 `[{"kind":"cross_store","threshold":300,"discount":50}]` |
| `coin_rate` / `coin_cap` | 否 | 淘金币抵扣比例与上限 |
| `member_price` / `live_price` | 否 | 会员价 / 直播价（若有） |
| `account_tier` | 否 | `normal` / `member` |
| `title` | 否 | 页面标题，用于 SKU 对齐 |

**空单元格 = 未知**，服务端会把它记入 `missing_fields` 并降低置信度。

## 四、投递方式

优先 **HTTP 直传**（能立刻拿到逐行校验结果）：

```
POST http://<lira-host>:8010/v1/import/csv   （multipart，字段名 file）
```

失败或服务未启动时，把 CSV **放进 `data/inbox/`**，后台调度每 15 秒扫描一次，
处理完会移到 `data/inbox/processed/`，失败移到 `data/inbox/failed/`。

上传前可先本地校验：

```bash
python validate.py snapshots.csv --server http://127.0.0.1:8010
```

## 五、失败处理

| 情况 | 影刀侧动作 |
|---|---|
| 元素找不到 | 重试 2 次 → 该字段留空 + 记录 `error_code=selector_missing` |
| 登录态失效 | **停止整批**，通知负责人 |
| 触发验证码 | **停止整批，不尝试绕过** |
| 单条超时（>30s） | 跳过，继续下一条 |

## 六、责任边界

| 项 | 归属 |
|---|---|
| 影刀客户端、采集机、淘宝账号 | **客户** |
| 采集频率与合规 | **客户** |
| 字段契约、解析、判断、告警 | **本系统** |

系统只接收原始观测，不提供任何站点专用的绕过手段。
